## 共享约定

- 本文中的路径是后端路由，不包含 `/api/staging/` 等部署前缀。调用方以当前环境的 API 基地址拼接路径。
- 现有 hello 无需登录，使用 JSON 响应。目前没有统一业务响应包裹、错误码、认证、分页或业务时间格式；新模块先确认需要的约定。多模块共同使用的规则在本文集中维护。
- 模块契约说明资源权限、字段含义、成功及失败行为；Pydantic 模型和路由声明生成当前实现的 OpenAPI，提供字段类型、必填项及已声明的响应。已有实现的完整字段表优先引用 OpenAPI，Markdown 补充业务含义和示例。
- OpenAPI 描述当前实现。已确认但尚未实现的契约在对应模块说明中明确标注，并关联任务；任务进度仍放 Issue/Project。

## GET /test/hello

用于检查客户端与后端连通性。

| 项目 | 约定 |
| --- | --- |
| 方法与路径 | `GET /test/hello` |
| 身份要求 | 无需登录 |
| 请求 | 无请求体，无必需查询参数 |
| 成功状态 | HTTP 200，`application/json` |
| 响应字段 | `message`：字符串，值为 `hello world` |

请求与成功响应：

```bash
curl -i http://127.0.0.1:8000/test/hello
```

```json
{"message":"hello world"}
```

未知路径返回 HTTP 404、`{"detail":"Not Found"}`；对 hello 使用 POST 返回 HTTP 405、`{"detail":"Method Not Allowed"}`。沿用 FastAPI 的 `detail` 响应，不为演示接口增加业务错误包裹。

网络不可达、客户端超时及无效响应的处理见[客户端调用说明](../frontend/src/api/README.md#hello-调用与失败处理)。测试网关提供 `X-Livelife-Backend-SHA` 版本头，本地 Uvicorn 不自动生成；配对规则见[部署入口](deployment.md#api-地址与前端关联)。

## 模块契约怎么组织

模块需要独立维护接口时，在实际后端模块目录放一份 `API.md`，由本文提供入口；多个相关接口共用该模块文档，不按每个端点或 Issue 建文件。模块尚未形成独立目录时，先保留本文中的对应章节，拆分随真实代码组织调整。

跨模块的业务需求或设计放在共享文档，模块契约链接过去。客户端超时、提示文案和页面状态在前端模块维护；部署控制、运行时配置及签名规则在 deploy 维护。

每份模块契约按以下内容组织，适用的规则才填写：

| 内容 | 要写清楚什么 |
| --- | --- |
| 用途与权限 | 使用场景、身份要求、允许访问或修改的资源 |
| 请求 | 方法、路径、参数位置、字段含义及校验约束；未实现时补充类型、必填、默认值和空值规则 |
| 成功结果 | 状态码、JSON 示例、关键字段含义及状态变化 |
| 失败结果 | 状态码、错误示例、触发条件；在路由中声明相应响应并验证实际返回 |
| 特殊规则 | 分页和排序、带时区的时间、地图坐标系、重复提交及幂等等 |
| 兼容性 | 调用方影响、迁移方法和旧行为保留期限，发生变更时写明 |

字段类型、必填项、默认值、错误状态和示例在同一 PR 核对模型、OpenAPI、模块说明及测试，避免两份定义长期不一致。公共入口仅在模块链接或共享规则变化时更新。

## 接口契约协作

以后续兴趣订阅为例，以下是协作流程示例，不表示该接口已实现：

1. 在任务中列明模块、交付内容、契约文件与章节，以及前后端依赖；指定公共契约负责人。
2. 前后端共同确认请求、响应、资源权限、校验和错误行为，提交契约 PR。涉及已确认契约的不兼容修改，先说明迁移和客户端影响，再确认方向。
3. 契约确认后，前端按它制作明确标识的 Mock，后端并行实现；各自提交对应模块的代码、文档和检查结果。
4. 联调时核对前后端 SHA，验证成功、校验失败和权限边界；将实际结果与未测项写入 PR/Actions。
5. 后续变化更新原章节和声明，同步受影响的调用方及测试；完成进度在 Issue/Project 更新。

地图接口还需确认坐标系、地点标识和活动关联；登录、分页及统一错误规则按实际业务需要确认，不提前虚构。
