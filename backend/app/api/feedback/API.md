# 用户反馈 API

## 提交与回执

`POST /feedback` 使用账户 Bearer 认证，仅代表当前登录账户提交；无匿名入口。客户端不传用户 ID、状态或提交时间，额外字段返回 422。

```json
{"client_request_id":"0b64d963-53de-4cbe-9e65-54fe8f2567f8","content":"活动日历里有一处显示问题"}
```

`content` 为去除首尾空白后 1–500 个 Unicode 字符，拒绝 NUL；`client_request_id` 为客户端每次新反馈生成的 UUID。可以在正文中描述信息标题或编号，首期不增加信息关联、纠错或下架接口。不自动收集设备信息、聊天、定位、日志或凭证；请勿在正文填写密码和敏感个人信息。

首次持久化完成后返回 **201**；同一账户、同一请求 UUID、相同规范化正文重试返回 **200**，回执不变：

```json
{"id":"b14c90b1-bc98-4366-a18a-d9d21d2d13fa","submitted_at":"2026-11-18T08:00:00Z"}
```

编号即反馈 UUID，时间为服务端接收时间（UTC）。回执不包含处理进度；用户端首期没有历史查询。回执使用 `Cache-Control: no-store`。提交成功只代表已保存，不代表已经处理。账户内请求 UUID 永不复用；相同 UUID 改变正文返回 409。客户端超时、断网或收到 5xx 后应保留正文与请求 UUID，重试原请求，不能直接宣告失败未入库。编辑正文代表新的提交。

每账户滚动 60 秒最多 **3** 条、滚动 24 小时最多 **20** 条新反馈，数据库内计数并通过账户行锁串行化；幂等重放先于限流判断。达到上限返回 429 和 `Retry-After` 秒数。不是基于可伪造的客户端时间或单进程内存。

| 状态 | 含义 |
| --- | --- |
| 401 | 未登录、会话撤销/过期或账户已删除 |
| 409 | 请求 UUID 已对应另一正文 |
| 422 | 正文或请求字段无效 |
| 429 | 新提交超过账户频率限制 |
| 503 | 数据库未配置或持久化不可用，可使用原请求 UUID 重试 |

错误采用 FastAPI 的 `detail`，不向客户端返回数据库语句、异常或凭证。`GET /feedback`、反馈详情和状态修改均不提供 HTTP 路由，普通用户不能读取或处理他人反馈。

## 维护、保留与部署

**首期维护入口只有服务器命令行，没有管理网页或管理员 HTTP API。** 持有数据库访问权限的可信维护者按[后端操作教程](../../../README.md#用户反馈维护)查看、筛选和更新状态；命令行的操作人标识只是审计字段，不构成身份认证。后续更方便的管理入口需要单独设计权限。

状态为 `pending`（待处理）、`processing`（处理中）、`resolved`（已解决）、`closed`（关闭）。维护操作须提供当前版本、操作人和原因；实际状态变化才增加版本并写入不可覆盖的处理记录，不发送邮件或应用通知。

反馈及处理记录保留到用户注销，注销事务中全部删除；不保留匿名副本。常规退出登录不删除反馈。备份仍按部署环境的备份生命周期管理，不能宣称已删除外部备份。迁移 `0011_user_feedback` 新建两张表、不迁移任何旧占位反馈。标准部署需先 `alembic upgrade head`，本地自动数据库启动器沿用自动升级；降级会永久删除反馈与处理记录，需事先备份。
