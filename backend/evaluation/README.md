# Agent 检索评测

本目录保存固定数据、冻结的关键词基线及离线评测入口。生产检索仍由
[`app/services/agent/retrieval.py`](../app/services/agent/retrieval.py) 提供。

## 数据与标注

[`campus.json`](campus.json) 是人工构造的中文校园样本，不是真实课程、活动或公告。
18 条主题资料和 501 条较新的干扰记录共 519 条，固定查询时刻为
`2026-11-18T14:30:00+08:00`。26 条查询包含 21 条有答案查询及 5 条无答案查询，
覆盖口语、简称、课程号、相邻教室号、今天/现在/明天、有效旧资料及缺失事实。
`relevant` 按资料的 `id` 标注能够支持该问题答案的记录；这些初始标注需要成员复核。

干扰记录比长期有效的续借、成绩单及奖学金办法更新，用于重现最近 500 条窗口的遗漏。
相同数据、问题、时刻和标注用于各方案对照。修改数据后版本和报告中的 SHA-256
必须一并核对；不要把不同数据集的结果直接比较。当前时刻字段用于定义时间标注；
现有关键词基线不处理时间条件；当前关键词/混合检索均注入该时刻，不使用运行当天日期。

## 运行与结果

在 `backend/` 执行：

```bash
uv run --locked python -m evaluation.retrieval --mode baseline --output /tmp/retrieval-baseline.json
uv run --locked python -m evaluation.retrieval --mode current --output /tmp/retrieval-current.json
uv run --locked pytest tests/test_retrieval_evaluation.py
```

Windows 将 `/tmp/` 改为已有的本地输出目录。程序创建独立临时 SQLite 数据库，
不使用 `DATABASE_URL`，退出后清理临时数据；报告只在指定输出文件或标准输出生成。
这两种模式不请求模型，也不更新共享数据库。`current` 使用当前检索函数的关键词模式，
向量效果使用下节的真实 PostgreSQL 与模型对照。地点目录作为共同测试条件导入，两种模式的数据一致。

[`keyword_baseline.py`](keyword_baseline.py) 冻结 main 的 `a816d8a` 对应实现，保留
500 条候选窗口、字段权重、排序、片段截断和来源构造。它仅供评测，不由应用导入；
后续实现不要修改它来提高对照成绩。

报告包含逐查询的标注、返回记录 ID、命中数、召回率、无关数和耗时，并按类别汇总：

- **Recall@8**：同一原记录的重复片段先去重，取前 8 条；命中标注数除以该查询的
  标注总数，再对有答案查询取宏平均。无答案查询单列，不以零作分母。
- **无关结果比例**：有答案查询返回的非标注记录总数除以返回记录总数。
  零返回时为 `null`，召回仍为 0，不能把零返回误解成高质量。
- **无答案候选数**：无答案查询中仍返回候选的查询数；返回话题相关资料不代表
  该资料含有答案。例如讲座介绍不能证明主讲人手机号。此指标提示证据不足风险，
  最终还需要逐条验证回答是否拒绝编造，不等同于生成模型的幻觉率。
- **p50/p95 查询耗时**：本次逐条调用的本机耗时，包含首次冷查询；不包含资料入库。
  SQLite 数字不代表目标 PostgreSQL、Embedding 服务或并发性能。

这套小型合成集只用于回归和初步比较。真实效果验收还需独立真实公开校园语料、
复核后的标注及未参与阈值调整的留出查询，不能以替身向量或本集调参成绩宣称模型改善。
目标服务器的索引构建耗时、延迟、内存及显存必须在目标环境另测并记录在 PR。

## 真实模型与 PostgreSQL 对照

先按[检索模块](../app/services/retrieval/README.md#本机安装与启动)启动独立模型服务，
当前终端设置相同的模型、revision、维度及查询前缀，并配置服务的 `EMBEDDING_BASE_URL`。
然后在 `backend/` 执行：

```bash
uv run --locked --group local-db python -m evaluation.retrieval \
  --mode compare-postgres --output /tmp/retrieval-qwen.json
```

此模式自动创建并迁移一个临时 PostgreSQL，**不使用配置中的 DATABASE_URL**，
真实调用所选的模型服务建立全部片段，然后在同一数据库上依次测旧基线、当前关键词和混合检索。
索引失败会终止，不把部分索引当成完整评测。每条新检索记录 `retrieval.mode/reason`，
若显示关键词降级，必须单列故障，不能当成模型质量成绩。

报告含固定模型 SHA、profile、维度、相似度门槛、索引记录数、索引耗时、逐查询延迟和本进程采样峰值 RSS。
可加 `--embedding-pid <本机模型进程PID>` 以 0.1 秒间隔采样模型 RSS；PID 取模型服务启动日志。
模型下载和首次加载不计入索引耗时；查询按固定顺序单次运行，p95 是最近秩统计，不代表稳态并发结果。
RSS 不等同于独占物理内存，GPU 显存标记未测。远程模型不能用本机 PID 采样；
在目标服务器运行相同命令、记录硬件/设备，并用其平台工具独立测显存和数据库资源。

BGE 对照服务使用 `BAAI/bge-small-zh-v1.5`，revision
`7999e1d3359715c523056ef9478215996d62a620`，维度 `512`，查询前缀
`为这个句子生成表示以用于检索相关文章：`。在另一个端口启动后切换客户端相同配置，再运行相同命令，
输出到另一个报告文件。两个候选分别构建全新索引，不共用向量；依次测量以减少 CPU 竞争。
初始门槛可以先用同一值对照，但不同模型分数分布不同，调优时记录所有阈值，不覆盖原始报告。
