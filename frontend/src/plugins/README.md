# 手绘 UI 渲染

本目录维护手绘指令、PNG 绘制队列与启动预热。持久化存储由[手绘缓存模块](../platform/SKETCH_CACHE.md)维护。

| 文件 | 职责 |
| --- | --- |
| [sketch.js](sketch.js) | v-sketch 指令及控件装饰 |
| [sketch-bitmap.ts](sketch-bitmap.ts) | SVG 转 PNG、队列与内存复用 |
| [sketch-warmup.ts](sketch-warmup.ts) | 隔离路由中的默认页面预热 |
| [main.ts](../main.ts) | 创建队列、恢复缓存与启动应用 |

## 手绘装饰渲染

`v-sketch` 继续按控件尺寸、颜色和状态生成原有的铅笔轮廓与彩铅纹理，但复杂 SVG 在页面外生成，由 `sketch-bitmap.ts` 转为透明 PNG，页面显示图片。噪声滤镜、遮罩和密集笔触在页面外处理，小型普通图标仍使用 SVG。

相同 DOM 位置与绘制状态使用稳定笔迹，图片缓存由整个客户端共用；返回页面时按尺寸、颜色、状态与笔迹种子直接复用已有纹理，跳过矢量生成、序列化和图片编码。首次生成的装饰整批显示，尺寸或选中状态变化才更新。生成失败不会隐藏文字、阻止点击或回退到原来异常的复杂 SVG。缓存按最近使用顺序回收无人引用的图片，限制像素预算；组件离开时释放使用引用，应用卸载时释放图片 URL。

## 启动预热

首次或没有完整兼容缓存时，用隔离的内存路由预热七个页面及“我的”八个子页面的默认装饰，显示准备进度；最多等待 30 秒，字体等待最多 1.5 秒，超时继续启动。预热不创建 2D/3D 地图或注册原生返回监听，也不提交资料、请求权限或调用 hello。子页面通过 `sketchWarmupScenariosKey` 注册纯界面准备步骤，离开时注销；新增子页需把默认视觉状态纳入该清单。图片缓存预算约 128 MiB 原始像素，优先回收无人引用的旧纹理。Agent 气泡和地图样例卡片按固定种子排列，在进程重启后也保持配色与顺序；交互弹层、新尺寸等额外状态仍按需生成。底部导航的底色、选中区域和轮廓合成同一张纹理，避免各层异步切换留下旧白底。

## 调整笔迹与主题

异步组件插入会改变相邻元素的 DOM 下标；这些控件使用稳定且唯一的 `data-sketch-key`，避免预热与实际打开时产生不同的笔迹标识。

后续新增 UI 主题时，将主题标识纳入装饰缓存键；先按新主题准备整套默认页面，再整体切换显示。当前没有多主题切换入口，这是一项后续实现约定。

## 日志与排查

启动控制台输出 `Livelife sketch preparation` 和 JSON：`generated` 为实际新编码次数、`diskHits` 为成功解码的磁盘命中、`memoryHits` 为会话内命中、`readMs`/`encodeMs` 为累计阶段时间、`elapsedMs` 为界面准备总时间。`restored` 为恢复的语义别名数、`restoreMs` 为整套缓存恢复时间；`Livelife sketch first page` 另记录当前页面首次绘制队列完成时的累计指标。耗时包含字体、布局和图片解码，不等于全部应用启动或地图加载时间。固定演示配色使用稳定种子，避免进程重启因随机配色产生新的默认装饰。

## 验证

修改公共手绘效果后，除类型检查和构建外，按[测试说明](../../../docs/testing.md#android-手绘渲染回归)检查手机拖动、页面往返、尺寸变化和生成失败。桌面浏览器通过不能证明 Android WebView 没有绘制兼容问题。
