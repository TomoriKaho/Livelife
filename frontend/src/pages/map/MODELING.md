# 燕园三维外观与景观建模

这版在真实 OSM 平面轮廓上，增加彩色立面、窗框、檐口、收坡屋顶、门廊、树冠、湖岸和光照。目标是可辨认、便于逐栋修订的校园设计模型；不是摄影测量或施工模型。当前颜色采用 UI 主题的亮黄、浅蓝与薄荷绿，是设计表达，不是建筑实景颜色。所有几何和材质本地生成，启动不请求外部照片、地图、贴图或接口。

## 真实数据与设计近似

| 项目 | 依据与精度 |
| --- | --- |
| 建筑位置、朝向、轮廓 | 本地 OSM way / multipolygon，保留凹形轮廓和内部庭院，坐标存储至分米；源数据本身不是测绘精度保证。 |
| 多面建筑 | 补充 relation 完整成员后，用端点拼接外/内圈。图书馆保留三个内圈，楼体、屋顶与悬空楼板不填满庭院。缺失成员的开放轮廓不被强行闭合。 |
| 高度与层数 | 原数据优先用 `height`，否则楼层数乘 3.8m，再否则常规模型按三层。保留 `heightSource` 区分来源；人工外观配置另作覆盖，不改写原始地图。 |
| 博雅塔 | 官方资料与照片为参考：八角塔身、十三重密檐、逐次收分、窗洞、基座和塔刹，总高约 37m。檐口尺寸及装饰简化。 |
| 教学楼、图书馆 | 灰砖/暖灰石色墙面、蓝灰玻璃、浅色窗框、层间腰线、女儿墙、设备小箱、台阶与门廊。颜色、窗格数量、入口位置、人工高度与屋顶形态为外观近似。 |
| 传统建筑、西门 | 灰绿收坡屋顶和外伸檐口、米灰墙体、棕红窗框。西门用门柱和横梁留出通道，增加牌匾。通用屋顶按边界距离抬高，不是精确传统屋架。 |
| 讲堂、体育馆 | 讲堂使用抬高的收坡屋顶表达体量，体育馆采用简化弧面屋顶。实际结构与各翼高度仍需逐栋修正。 |
| 未名湖 | 实际水面轮廓、青绿水面、窄岸带、弱波纹。没有真实水深、动态倒影或岸边高差测量。 |
| 植被 | 优先 OSM 树点与树列，余下为固定种子补植，湖岸增加垂柳形态。避开楼体、水面、运动场和道路通道。树种、株高、树冠和补植位置为示意。 |
| 校外背景 | 实际 OSM 轮廓与推定高度、不同暖灰墙色，合并绘制；校外暂不使用校内的详细窗格和屋顶模型。 |
| 室内与活动 | 沿用设计演示数据。楼板沿真实轮廓生成，房间网格、悬空间距和活动为示意。 |

## 文件分工

- `model-profiles.mjs`：以 OSM ID 为键的地标类型、人工高度和层数；保留原实景颜色配置及 OSM 颜色读取，最终展示颜色由主题覆盖。
- `map-palette.mjs`：集中维护亮黄楼体与现代屋顶、薄荷色传统屋顶、白色窗格及明亮景观颜色。调整展示配色优先改此文件，原地图快照保持原样。
- `architecture.mjs`：挤出、窗格、材质、屋顶、博雅塔、西门。增加单栋细节时优先写独立模型函数，不把地标尺寸混进通用生成器。
- `storeys.mjs`：初始化时裁切完整外壳、插值法线与颜色、合并每层几何；维护同一楼层/屋顶对象的展开与收起动画。
- `pencil-material.mjs`：统一彩铅哑光材质、方向性漏色、纸齿与轻微黑铅结构勾线。调手绘强度优先修改此文件。
- `landscape.mjs`：固定种子树木布局、实例化树冠/树干、水面与岸带。
- `rings.mjs`：环拼接与含庭院的 footprint 判断；供地图处理、楼板和景观共用。
- `CampusScene.vue`：光照、相机、选取、分层、聚焦和资源释放。业务页面与演示活动仍分别在 `../MapPage.vue`、`demo.js`。

墙面、屋顶、窗格、室内、水面、道路和植物统一为彩铅漫反射材质，取消玻璃与水面的金属感和强高光。楼体在 UI 黄色的四种笔触色中按 OSM ID 稳定选色，现代屋顶用品牌黄，传统屋顶用薄荷绿，窗格用与 APP 背景一致的白色 `#ffffff`，湖水用天蓝 `#7dd6fa`；草地与五种树冠绿色进一步提亮，道路使用白色 `#ffffff`。天空与远景雾使用 APP 主样式蓝 `#9ac8f2`，雾在 650–2000m 间渐隐。纸色预混从 13% 减至 4%，基础露纸混合为 0.10，避免主题黄被过度冲淡。使用直接色彩输出而非摄影式 ACES 映射；最终颜色保留 55% 本色、45% 漫反射光照，使阴影柔和且不把亮黄压成土黄。模型轮廓轻勾黑铅，实体折角和檐口描边，平滑曲面不铺三角网格。树冠增加细分使轮廓圆润，背面外壳实例化描边。地图与外层 UI 共用 `design/DESIGN.md` 的视觉规则，但三维材质用本地 GLSL 程序绘制，按钮仍用公共 SVG，不把 SVG 贴到建筑表面。

彩铅笔触在每个表面的局部坐标中固定，主要为约 -30° 的宽笔触连续平涂、深浅搭接和细纸齿；少量露纸沿涂抹方向拉开，不使用随机白洞。`fwidth` 根据屏幕采样密度衰减细颗粒与笔触，降低远景与缩放中的摩尔纹。没有按帧随机数或时间噪声，楼层位置变化也不重新上色。勾线由真实结构边提取，长线分段并添加最大 0.045m 的稳定小偏移，保持端点连续。

通用收坡屋顶将轮廓三角面细分两次，再按距外墙/庭院边缘的距离抬高；檐边增加约 0.9m 外伸带，保持庭院开口。屋脊不代表实际测绘结果。博雅塔和弧面体育馆使用独立几何。

树木由三组主体 InstancedMesh 和两组树冠描边绘制；墙面、窗框与腰线按层合成带顶点颜色的几何，周边楼体仍合并绘制。四个活动建筑在初始化时缓存室内部件，其他建筑首次展开时缓存一次；后续切换复用缓存。首次展示前预编译场景材质。静止浏览不重复计算整校阴影，场景变化和分层动画期间更新。组件卸载释放几何、材质、牌匾纹理、控件和 WebGL 资源。

## 交互

初始定位附近视角、校界拖动限制、普通楼层交互沿用原设计。校界不裁断周边景观。普通建筑聚焦时隐藏周围楼体和树冠，保留地形、道路、水面及本栋彩色屋顶；1F 在地面，其余楼板和屋顶悬空。

默认相机仍围绕前端示例定位点，偏移为 `[165, 95, 110]m`，高度约 95m、距离约 220m、俯视角约 26°，便于直接看到附近立面和彩铅笔触。返回和定位按钮共用此视角。定位蓝点半径为 4.5m，光环为 7–10m，避免在拉近后遮住建筑。

完整外观从初始化开始就由可移动的楼层对象和独立屋顶组成，不在点击后用另一套模型替换。水平裁切插值原立面的法线与颜色，跨层长窗仍保留；图书馆庭院始终空开。重复的挤出顶盖在初始化时去掉，完整外观由原屋顶封顶，展开后最上层也可看到室内。西门牌匾保留其原本地文字纹理并随所在层移动。台阶与门廊保持在基座。

每层紧凑坐标为 `(floor - 1) × 建筑高度 / 展示层数`，展开增量为 `(floor - 1) × max(16, max(平面宽, 平面长, 45) × 0.42)`；屋顶的增量为 `展示层数 × 同一间隔`。因此展开后的层间距包含原始层高，并非把原模型压扁为薄板。位置缓动使用 `t² × (3 - 2t)`，默认 1050ms；收起、中途反向和跨建筑选择都从当前进度继续。楼层标签投影使用实时位置。地图画布保持高度，避免相机纵横比在点击瞬间改变。`prefers-reduced-motion` 下动画直接完成。

博雅塔作为风景地标：点击模型或搜索“博雅塔”聚焦完整外观，保留湖岸与周边楼体。十三重密檐不虚构成教室活动层，下方显示地标说明和返回按钮。2D 继续留白。

## 离线数据

`yanyuan-details-osm.json` 保存补充快照，`details-source.json` 保存查询、接口、下载时间和数据时间。查询使用 `out body geom` 以保留 relation 成员 geometry；原 `out tags geom` 只有关系标签与包围盒，不能恢复庭院。

`npm run map:prepare` 只读取本地两套快照。`npm run map:download` 才显式刷新主快照和补充快照后生成展示数据。构建将两套原始快照、来源和许可证一起保存至 `dist/assets/maps/`。当前为 250 栋校内建筑、826 栋周边背景、47 个原始树点；最终树冠包含补植，不能视为实测树木统计。

## 核验

`npm run test:map` 还检查裁切表面积守恒、长窗跨层连续、裁切楼层不填庭院、全校楼层几何合法、原屋顶/外壳几何/材质的引用复用、动画中途反向及减少动画直接完成。浏览器另核验实际 WebGL 材质编译、快速收起重选的模型 ID、地标聚焦、普通楼层选择和 3D/2D 往返。CPU 几何测试不代替真实手机帧率测试。
