# D-02 活动地图设计

## 本地信息系统联调

地图使用 #82 的前台定位状态，通过 `POST /events/nearby` 查询后端地点库中的活动。2D 建筑计数、3D 建筑标记、附近列表和建筑选择共用返回结果。条目提供原文链接、活动日期、地点原文和教室，合成条目标为“合成演示条目”。楼层未知时显示“楼层未确认”，建筑展开仍为地图示意。

先在 `backend` 目录运行 `uv run --locked python -m app.content_demo --port 18764`。再在 `frontend` 目录运行以下命令，打开 `http://127.0.0.1:8775/#/map` 并允许定位。

```bash
VITE_API_BASE_URL=http://127.0.0.1:18764 npm run dev -- --port 8775
```

需要公众号样本时，按[信息系统说明](../../../../backend/app/services/content/README.md)给后端追加 `--wechat-json`。这个入口提供地图所需的本地信息接口，账号和 Agent 功能使用标准后端入口联调。

- 首次有效定位后自动查询。移动至少 25 米或上次查询满 30 秒后的新定位会刷新，半径、关键词和日期变化合并 350 毫秒后查询。
- 筛选默认 300 米、包含历史活动。展开“筛选”可修改半径、关键词或选择“仅今天”，当天边界采用北京时间。展开活动抽屉可阅读完整条目。
- 请求前清除旧结果并取消上一请求，迟到响应按请求代次丢弃。十秒超时、后端错误、无结果、权限拒绝、位置过期各有提示，可以重新定位与刷新。
- 设备位置超过两分钟或超过允许的未来时钟偏差时，清除附近结果并要求刷新。定位精度与搜索半径分别处理。校外位置照常交给后端筛选，离线地图提示展示范围限制。
- 附近查询向配置的后端发送查询中心、精度和时间戳，设备轨迹不入库。地图内部绘制仍用原有米制投影。

联调验证可在浏览器 Sensors 输入 WGS-84 讲堂坐标 `116.30452, 39.98857`，100 米范围应返回讲堂官方演出样本。移动到图书馆 `116.30396, 39.99052` 应切换为图书馆讲座。检查关键词空结果、仅今天、断网重试、过期位置、2D/3D 切换及“在地图查看”。浏览器模拟位置验证请求链路，真实设备定位和方向传感器另行验收。

## 交互状态

1. 应用根组件维持前台位置监听，地图订阅最近位置并显示蓝点、精度圈与朝向。首次取得位置和主动定位时居中，持续移动更新标记与附近查询。
2. 附近活动抽屉显示统一信息系统结果，筛选条件变化由后端计算。选择活动的“在地图查看”聚焦对应建筑，返回可查看全部附近结果。
3. 建筑搜索支持地图名称及当前返回活动的标题、地点。点击建筑后列表按建筑 ID 展示匹配活动。
4. 右侧控件可缩放、切换 2D/3D 和重新定位。两种视图共用位置与活动，切换视图复用已有查询结果。
5. 楼层模型仍为示意，真实条目展示来源给出的房间或楼层。未知楼层的活动仅在建筑级聚合。
6. 活动来源可在新页面打开。公开活动无需登录，其他页面按各自的账户契约处理。

## 几何与真实信息边界

底图保存于 `src/assets/maps/`。原始查询矩形包括校外范围，处理脚本使用 OSM 的「北京大学」校界区分校内互动建筑与周边背景建筑，而非把整个查询框当作燕园。建筑按轮廓中心区分；水面、绿地也分别归入校内及周边集合。校界附近的单个跨界建筑/面要素保留原轮廓，并非对每个面做严格布尔裁切。

校界只约束地图拖动中心，不切断画面。地面连续延伸，周边按实际 OSM 轮廓生成简易模型，远处使用同色雾淡出。`context.roads` 在原始下载范围内保留跨校界道路连续性，场景只渲染这一套道路，避免叠加重影；原 `roads` 仍保留校内裁切结果作数据校验。周边建筑作为背景，不参与校园楼层活动的选择与搜索；背景模型合并绘制以降低绘制调用数。

平移使用地面平面。每帧在 OrbitControls 应用拖动和惯性之后，检查目标点是否位于燕园校界内；校外点回到最近校界，相机同步平移同样的距离，保留观看角度。使用实际凹形多边形，不使用矩形包围盒限制。

当前快照保存 250 栋校内建筑、1639 条校内道路段、12 处校内水面，并新增 826 栋周边背景建筑。包含周边的场景渲染道路共 5481 段。未名湖、博雅塔、理科教学楼、百周年纪念讲堂等来自实际 OSM 数据。米制坐标原点为 `[116.304, 39.9915]`，x 向东、z 向南。坐标保留分米精度；不依赖在线瓦片、地图 SDK、字体服务或 CDN。底图复用原离线快照，并补充建筑多面关系与树木快照。

`demo.js` 的 `demoLocation = [175, 135]` 仅作未定位时的初始视角。`view.mjs` 定义相机相对偏移 `[165, 95, 110]m`，初始相机高度约 95m、观看距离约 220m、俯角约 26°，默认即可看到附近楼体与彩铅笔触。设备坐标采用浏览器的 WGS-84 经纬度，复用 `geometry.mjs` 的原点投影转为 x 向东、z 向南的米制坐标；蓝点半径为 4.5m，精度圈半径采用系统返回的 `accuracy`（米）。

OSM 有 `height` 时使用该高度；否则按 `building:levels × 3.8m` 推定，没有楼层标注时常规地图模型暂按三层。为了演示楼层，理教设四层、讲堂三层、二教五层、一教三层。其余校内建筑按外观配置或 OSM 层数展开最多六个示意层；博雅塔保留完整外观、聚焦观看，不虚构教室层。**这些不代表真实楼层数、室内平面、层高或活动安排。** 内部分隔按轮廓内规则网格生成，不是建筑测绘模型。

楼层展开在原始层高上叠加 `max(16m, max(建筑最大平面尺寸, 45m) × 0.42)` 的额外分离距离。楼体在初始化时按层裁切，点击后不替换原模型；收起时反向归位，中途重新选择从当前进度继续。相机根据平面范围、总分层高度、纵横比和视场角计算容纳整个模型的距离，使用较低的观看角度，减小上层遮挡。用户可继续旋转查看。已增加窗格、檐口、彩色屋顶、树冠与湖岸；来源、程序化生成方式和精度边界详见 [MODELING.md](./MODELING.md)。

## 文件分工与离线启动

- `../MapPage.vue`：搜索、分类、模式切换、共享位置的地图投影与展示、底部信息区、详情弹窗、页面状态与专属样式；应用级监听在 `../../platform/location-tracker.ts`。
- `CampusPlan.vue`：Canvas 2D 俯视绘制、可视范围裁剪、标签避让、指北针/比例尺、单指平移及惯性、双指/滚轮缩放、建筑点选与定位。
- `plan-view.mjs`：屏幕/米制坐标投影、缩放锚点、双指手势、校界约束、建筑命中（排除庭院）、米制比例尺。
- `plan-pencil.mjs`：地图色面的固定彩铅纹理和轻微黑铅路径；不修改原始轮廓数据。
- `CampusScene.vue`：Three.js 模型、OrbitControls、射线选取、相机动画、楼层分离及随相机投影的 DOM 标签。标签复用公共手绘纹理，并缓存按钮子树，避免每帧重画彩铅 SVG。
- `demo.js`：演示建筑、楼层、教室和活动；团队改内容优先在此维护。
- `view.mjs`：以示例位置为目标的初始相机偏移。
- `geometry.mjs`：坐标转换、点在多边形内判断、道路线段裁切、将校外拖动中心约束到最近校界。
- `map-palette.mjs`、`model-profiles.mjs`、`architecture.mjs`、`storeys.mjs`、`pencil-material.mjs`、`landscape.mjs`、`rings.mjs`：建筑外观、几何与风景，分工及精度见 [MODELING.md](./MODELING.md)。
- `scripts/prepare-campus-map.mjs`：从已下载的原始数据生成展示资源。
- `scripts/download-campus-map.mjs`：仅显式刷新数据时访问 Overpass，下载后自动生成展示资源。

在 `frontend/` 下：

```powershell
npm ci                 # 初次安装依赖需要网络；已有 node_modules 时可跳过
npm run dev            # 地图启动与使用不需要互联网
npm run map:prepare    # 从本地快照重新生成，无网络
npm run test:map       # 校界裁切、投影、资源及活动映射检查
npm run build:preview
npm run preview        # dist 中包含地图、字体和 Three.js
```

仅需要更新底图时执行 `npm run map:download`，此命令需要网络。常规启动与构建绝不运行下载脚本。离线是指依赖已安装后的本地启动，仍通过 Vite 或静态 HTTP 服务提供网页，不是双击 `file://`。

OSM 署名及 ODbL 许可证说明见 `src/assets/maps/LICENSE.md`。生产构建保留原始地图、转换数据、来源说明和许可证，便于团队分发和追溯。

客户端地图在地图仍可见时，于地图区右下角显示 `© OpenStreetMap contributors` 署名及版权链接。署名与左下提示跟随当前抽屉遮挡高度 `--drawer-occlusion`（由 `ActivityDrawer` 的 `layout` 事件驱动，包含当前档位 `state`、实际遮挡高度 `occlusionHeight` 和全展开高度 `expandedHeight`），隐藏档贴在把手上方、默认档贴在半展开高度上方，不与搜索框或缩放控件重叠。通过 `ResizeObserver` 观察抽屉实际尺寸，使署名在拖动和松手后的吸附动画中持续跟随；`map-drawer-layout.mjs` 根据实际高度判断地图是否露出，全展开遮盖地图时不显示署名。相机视口仍用默认档 `middle` 作 `focusInset`，与浮层位置解耦。共用 `OsmAttribution.vue`，文案与链接只在 `osm-attribution.ts` 维护。构建保留地图来源和许可文件。分发时保留这些入口，参考 [OSMF 署名指南](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines#Introduction)。

## 视觉基线

公共字体、按钮和卡片继续遵守 `DESIGN.md`：本地 Xiaolai 圆润手写体、轻微且圆滑的铅笔勾线、饱和黄/浅蓝/薄荷绿/粉色、斜向彩铅平涂的深浅与少量漏色，不整体倾斜。3D 楼体使用 UI 主题亮黄，现代屋顶为品牌黄，传统屋顶为薄荷绿，窗格为与 APP 背景一致的白色，湖水为明亮浅蓝，绿地与树冠一起提亮。展示配色集中在 `map-palette.mjs`，独立于原始 OSM 颜色；弱阴影保留主体填色的明度。全局透明背景保持；WebGL 地图区域的天空与远景雾采用 APP 主题蓝 `#9ac8f2`；明亮草地、树冠和天蓝水面搭配白色道路。模型使用固定在局部表面的宽笔触斜向彩铅平涂、少量同向漏色与轻微黑铅轮廓；水面和窗格为哑光，树冠圆润，参数统一在 `pencil-material.mjs`。

地图页通过 `pageMeta.immersive` 压缩公共标题栏并省略占位页脚，保留页眉与固定底部 Tab。地图固定在正文区域，下方信息通过 `ActivityDrawer.vue` 展示三个档位：默认中间档为手机框架高度的 1/4，上滑展开至页眉分割线，下滑隐藏至 Tab 上方的 38px 把手。展开高度按实际页眉与 Tab 尺寸计算，不再使用 3/4 比例。抽屉白底采用无圆角的直线黑铅上沿，完整遮挡地图背景。提示为「上滑发现更多，下滑隐藏内容」；隐藏档只露滑动把手，内容不可聚焦。顶部把手可拖动或点击，也支持键盘上下箭头。

抽屉内容在展开后独立竖向滚动；内容滚到顶部后下拉可换档，中间档上滑展开、下滑隐藏。横向翻看活动卡不会触发纵向拖动。释放后按手势方向吸附至三个高度，短滑动换一档，长距离拖动可跨过中间档；使用 620ms 的平滑高度动画，拖动时实时跟手。隐藏档点击或上滑可恢复内容。点击活动或建筑进入探索时记录原抽屉档位，再平滑切到默认 1/4 档；连续切换建筑或从详情返回楼层地图不会覆盖原档位。点击「返回」或取消建筑选中时，抽屉带动画恢复进入探索前的档位，地图保留当前视角。复位 / 定位入口保持操作当下的抽屉档位，仅收拢模型并复位地图，同时清除旧的探索记录；切换地图模式保留探索与档位记录，继续查看同一栋建筑。

地图画布完整延伸至 Tab，通过 `CampusScene` 的 `focusInset` 与相机视口偏移，把聚焦中心保持在默认抽屉上方，同时绘制被覆盖的下方地图。换档不改变画布尺寸或相机，隐藏后显示完整地图，不出现蓝色空白。2D 也共用这一抽屉与固定覆盖范围，完整画布延伸到 Tab。320px 宽度仍保持单列，不生成桌面布局。

`npm run test:drawer` 检查三档尺寸、页眉及 Tab 边界、拖动限幅、横向/纵向手势吸附及隐藏档恢复规则。`npm run test:osm` 检查署名文案与版权链接；`node --test scripts/map-drawer-layout.test.mjs` 检查遮挡高度与署名可见性策略。


## 2D 俯视地图规范

2D 直接读取 `src/assets/maps/campus.json`，与 3D 共用校内/周边建筑、完整道路、水体、绿地、树冠位置、配色和设备定位蓝点/精度圈；运行时无需在线瓦片或额外下载。北向固定朝上，x 向东、z 向南，没有旋转或透视。建筑多面关系的庭院用 even-odd 填色保留空洞，命中测试也排除这些孔洞。校外建筑淡化显示，校界只限制观察中心，不裁出空白边界。

未取得位置时初始中心为 `demoLocation = [175, 135]`；已取得位置时以实际位置为中心。初始倍率为手机宽度 / 720，即约 720m 的横向范围，兼顾理教、图书馆与未名湖周边。倍率限于 0.22–3.2 px/m。投影中心位于顶部控件和默认抽屉之间；换档不缩放或重新生成地图。点击建筑平滑聚焦 720ms，关闭选中保留当前俯视位置；定位按钮平滑移到实际位置且保留抽屉档位。减少动画偏好开启时取消聚焦过渡与拖动惯性。

建筑色面采用 `profileFor()` 的屋顶色：现代建筑为亮黄，传统/地标屋顶为薄荷色，边缘带主题黄色墙体轮廓。只描建筑边缘、简化屋脊和设备轮廓，不增加三角网格或厚重投影；选中建筑使用蓝色轮廓。道路白色，草地与圆润树冠明亮浅绿，湖水浅蓝并带少量水纹；周边建筑使用浅纸色。标记和文字使用原 `v-sketch` 与本地小赖字体，优先显示选中建筑、活动建筑、主要地标；放大后补充其他建筑名称，避让搜索/控制器/指北针/提示/比例尺，控制标签密度。

纹理固定在地图坐标中：256×256 的 Canvas 图案重复；地景纹理块约 77m，黄色屋顶单独放大到约 256m，避免缩小采样把笔触平均成纯色。黄色在原有色面上叠加与 UI 一致的四阶颜料（`#ffd600`、`#ffdf16`、`#ffe93d`、`#fbd21a`）：-30° 的圆头宽笔触为 12–17m，分段长 32–80m、搭接 8m，透明度 .2–.44；默认视角可辨识约 5–10px 的笔触。露纸同向延伸，长 14–38m、宽 .9–2.4m，两端渐尖，断续排列，混入暖纸色，避免随机白洞。最后覆盖细纸齿，使搭接与漏色也保留颜料颗粒。其余色面维持原有约 2%–35% 的纸色混合与细纹理，不增加背景噪声。轮廓路径只在长边上轻微起伏（上限约 0.18m），圆头圆转折，屏幕上的黑铅宽度基本保持 1px。缩放只改变视图；图案、轮廓与树冠形态不会重新抽样。

Canvas 按设备密度绘制（最高 2 倍），预缓存 Path2D 和色面图案，绘制时剔除可视范围外的要素，只在视图/筛选/选中/尺寸改变或动画进行时更新。单指/鼠标拖动支持短惯性，双指缩放围绕手指中点进行，同时支持中点平移；滚轮以鼠标下的地图点为缩放锚点。方向键平移，加减键缩放。校内建筑可直接点轮廓，也可通过具名 DOM 按钮和原搜索/抽屉选择。

`npm run test:plan` 检查北向投影、坐标互逆、锚点缩放、双指平移缩放、倍率上下限、凹形校界、庭院命中与比例尺；浏览器检查手机布局、从非地图页的首次定位权限、允许后的蓝点/精度圈与首次居中、位置变化后的蓝点更新与不抢占相机、3D 中精度蓝圈与楼体相交时的半透明建筑与定位标、拒绝提示、点建筑/切换楼层、切换 3D/2D、点击定位、缩放定位和抽屉恢复。


## Android 加载与绘制

楼层裁切及其铅笔轮廓由单个 Web Worker 顺序准备，几何缓冲区通过转移返回主线程；不在 Worker 中创建 DOM 或 WebGL 上下文。普通地形、道路和周边准备按约 5 毫秒检查是否让出线程，附近建筑卡片和抽屉可在加载期间操作。离开地图会终止 Worker、取消剩余初始化并释放场景资源及候选几何。

地图静止时不持续绘制；相机拖动/惯性、定位/缩放、建筑展开、楼层高亮、活动更新及窗口尺寸变化安排下一帧。GPU 编译、上传和 Three.js 的部分场景准备仍在主线程，应单独记录实际设备的加载时长、短暂停顿和加载时操作列表的响应，不能用网页构建成功替代实机响应验证。

公共手绘装饰见[手绘渲染](../../plugins/README.md)及[静态资源](../../assets/sketch/README.md)。

## 外部网页与地图故障区分

地图使用包内数据，不依赖在线 OpenStreetMap 瓦片。地图露出时，右下角的署名链接通向外部版权页；Android 的 Capacitor 默认导航策略把外部地址交给系统浏览器，配置不应把外部域名加入 `server.allowNavigation`。验收时点击署名、返回应用，再检查地图与底部导航。外部网站超时应只影响浏览器，不应替换应用的本地页面。

临时绘制诊断应用使用普通 WebView，与正式测试包的外链策略不同，不能用其外部网页错误认定 APK 地图崩溃。若实际 APK 出现同样问题，记录包版本、完整错误地址和操作步骤，并检查 WebView 错误与进程退出日志；不要仅凭网站超时推断地图渲染进程崩溃。
