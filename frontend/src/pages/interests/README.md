# 兴趣广场

`InterestsPage.vue` 从 [内容 API](../../../../backend/app/api/content_feed/API.md) 读取公开信息，`FeedCard.vue` 只展示纯文本摘录与安全原文外链。空库不会使用 `demo.js`；旧原型资源暂保留供参考，不参与内容读取。

搜索输入防抖 300ms，平台标识和完整来源名称精确匹配，空白条件省略；每页 20 条，点“加载更多”继续。`useContentFeed.ts` 取消旧请求并用代次拒绝迟到响应，包括尚在平台配置检查中的请求；卸载时清理请求和防抖。十秒超时与失败可重试，翻页失败保留已有内容并重试同一页。更换条件立即清空旧结果，刷新从第一页读取。

没有服务端标签关联，不提供原型标签筛选。推荐、自定义兴趣和账号文章收藏标注为暂未开放；已有个人资料接口不在这里伪装成推荐生效。

## 本地验证

按后端 README 启动本地数据库/API，按[信息系统操作](../../../../backend/app/services/content/README.md#三个官网信源接入标准后端)采集并核对公开内容后入库。前端配置对应 API 地址，运行 `npm run dev`，打开兴趣广场：

1. 核对真实标题、来源与摘录，点阅读原文打开对应官网。
2. 输入正文关键词和卡片上的平台/来源，核对组合查询；清空恢复全部。
3. 数据超过 20 条时加载更多，确认无重复卡片；快速切换关键词确认旧结果不回填。
4. 关闭后端后刷新，确认错误和重试；重新启动后重试恢复；查无匹配时显示空结果。
5. 缺失标题、来源、正文摘录和链接的独立测试数据应显示缺失文案，不能生成虚构链接。

构建执行 `npm run build:preview`。浏览器回归脚本 `scripts/content-feed.browser.mjs` 使用替身验证分页、断网、超时与迟到响应；替身不等于真实内容联调，Android 原文跳转和真机仍需单独验收。
