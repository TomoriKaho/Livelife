# 静态手绘装饰

资源位于 `default/`，用于 #44 的公共控件与导航静态化。`manifest.json` 记录尺寸与 PNG 字节数：6 种轮廓（含五色偏移笔迹）、5 种填充纹理、5 种日历色点、1 张导航顶部轮廓，共 17 张。全部为透明 PNG、3 倍分辨率，总压缩大小约 162 KB，全部原始像素合计低于 3 MiB RGBA；不代表浏览器实际总内存。

## 来源与重新生成

轮廓改编自迁移前 `src/plugins/handdrawn.js`（已删除） 的采样与复描算法，使用固定种子；纹理由本项目脚本的固定像素噪声和周期笔压生成，没有引入第三方图片或字体。保留仓库原算法的版权／许可要求。离线渲染工具 `@resvg/resvg-js` 使用 MPL-2.0，仅为开发依赖，不进入客户端运行时代码。

在 frontend 目录执行：

```bash
npm ci
npm run sketch:prepare
```

脚本为 [prepare-sketch-assets.mjs](../../../scripts/prepare-sketch-assets.mjs) 与 [sketch-vector.mjs](../../../scripts/sketch-vector.mjs)。普通构建直接使用提交的 PNG，不联网生成、不在设备上转码。修改算法后重新生成 PNG 与清单，并核对差异和测试；不要只手改清单。调整轮廓尺寸需同步 `static-sketch.css` 的切片：源图 288px，切片 60px，对应 20 CSS px。

## 使用约定

卡片边框使用九宫格；纹理独立按固定尺度平铺。不要为每种文本高度或手机尺寸导出一整张高分辨率卡片；图标和文字继续由页面渲染，不烘焙进图片。装饰层不接收点击，图片失败不隐藏内容。

当前只有 `default` 主题，由 `main.ts` 设置根元素的 `data-sketch-theme`。`static-sketch.css` 将轮廓、五色填充、导航顶部轮廓和纸色映射为 `--sketch-asset-*` / `--sketch-surface` 变量；日历色点按相同主题目录提供。未来主题沿用这套资源集合和变量契约，本任务不新增主题入口或切换动画。导航选中项的纸色衬底遮住黄色底板，独立蓝色纹理不会与黄色混色；只有当前项保留装饰层，没有异步图片任务或旧状态缓存。详见[装饰清单](../../plugins/README.md#装饰清单与替换范围)。不同宽度、像素比与状态必须完成网页和真机外观验收；当前资源不声称逐像素复现旧笔迹。

## 旧版本缓存处理

新版本不打开或写入 `livelife-sketch-cache` IndexedDB，也不读取旧准备标记。覆盖安装保留的旧装饰数据不参与显示；无需清缓存即可使用新版本。需要释放旧磁盘空间时，可先关闭同来源的其他应用页面，再在开发者工具 Application → IndexedDB 中仅删除 `livelife-sketch-cache`。不要为清理装饰而使用 Android“清除应用数据”，它可能同时删除业务数据。应用不自动删除旧存储，不增加启动清理任务。
