# 平台能力适配

此目录放网页与 Capacitor 原生包共用的能力适配；页面只调用其公开函数，不直接处理原生插件或平台权限差异。

## 前台定位

[location.ts](location.ts) 提供按需的 `getCurrentLocation()` 和持续的 `watchCurrentLocation()`。后者只负责归一化平台回调，并返回停止函数；不保存任何位置。[location-tracker.ts](location-tracker.ts) 在 `App.vue` 挂载时建立全应用唯一的前台监听，并暴露响应式的最近位置 `currentLocation` 与状态 `locationTrackingState`。因此路由切换（包括离开地图）不会中断监听；根应用卸载时会清理监听。

- 成功结果含纬度、经度、精度、时间戳，以及平台提供时的航向；调用方负责把经纬度转为各自需要的坐标或文案。地图默认请求精确位置；Android 持续监听目标间隔及最短回调间隔均为 1 秒，但系统可为电量或信号质量合并回调。
- 错误为 `unsupported`、`permission-denied`、`unavailable` 或 `timeout`；不向页面透传底层异常信息。
- 已授权时会以时间戳更新内存中的最近位置：迟到的缓存样本不能覆盖更新的样本；持续监听已有有效位置后出现 `timeout` 或 `unavailable` 时保留最后坐标和当前界面状态；主动获取（如点击定位、刷新附近活动）失败必须显示对应错误，即使已有坐标也不吞掉。后续被动错误不清除主动错误，新位置成功后才恢复“已定位”。权限拒绝与不支持照常提示。最近位置仅保存在内存中。地图附近查询把经纬度和时间戳发送到配置的后端；精度保留用于地图显示，定位模块自身负责采集。该能力不是后台定位：浏览器或原生系统在应用不可见时的行为由平台决定。

网页的一次获取与持续监听分别使用浏览器原生 `navigator.geolocation.getCurrentPosition()`、`watchPosition()`，首次监听会按浏览器规则请求位置授权。Android 原生容器使用本项目 `DeviceLocationPlugin` 的系统 GPS/网络提供器；其他 Capacitor 平台仍使用 `@capacitor/geolocation`。Android 会请求精确位置，用户仍可在系统弹窗中选择粗略位置，此时精度以系统结果为准。定位按钮会先用已有的有效监听位置立即居中并恢复固定视野，再请求一条新位置；若尚无有效位置，则在下一条有效监听结果到来时居中。iOS 工程尚未创建，接入时必须在 `Info.plist` 增加“使用期间位置”用途说明。

坐标契约：平台定位和离线 OSM 地图都使用 **WGS-84**，页面不会自动把位置改为 GCJ-02。以博雅塔为例，WGS-84 测试坐标是纬度 `39.992637`、经度 `116.305783`；常见 GCJ-02 坐标 `39.993923, 116.311832` 与其相距约 500 米，不能直接用于模拟器或定位测试。

自动测试：`node --test scripts/location.test.mjs`。网页手动验证可在 Chrome DevTools 的 **Sensors** 设置模拟坐标：从任一非地图页首次进入应用时确认授权请求，修改模拟坐标后再进入地图，检查蓝点与精度圈采用最新位置；停留在地图时再次修改坐标，蓝点应更新且不会抢走用户手动调整的视角，点击定位按钮才重新居中。另验证拒绝、超时或不可用提示。Android 持续监听仍须在真实设备上验收。

### Android 首次定位超时排查

Android 使用 [DeviceLocationPlugin.java](../../android/app/src/main/java/io/github/tomorikaho/livelife/dev/DeviceLocationPlugin.java) 直接订阅系统 `LocationManager` 的 GPS 和网络提供器，绕开 Google 融合定位与服务检查。部分真机虽然拥有 Google 服务及有效系统网络位置，插件的融合定位调用仍可能长时间不返回，连其传入的超时也不生效；单纯增大超时或改为平衡精度不能解决此类阻塞。网页和其他原生平台的实现保持不变。[Android 接口说明](https://developer.android.com/reference/android/location/LocationManager)是系统提供器的依据。

Android 默认首条位置等待 20 秒，允许最近 15 秒的系统缓存；显式选项优先。原生主线程定时器负责超时，单次请求会结束并释放订阅；持续监听会发送超时事件结束界面等待，同时保留订阅，后续真实位置仍可恢复。GPS 与网络同时订阅，只授予粗略权限时使用网络提供器，不以 Google 服务状态作为前提。底层回调明确保留系统时间戳与实际精度，不用演示点代替真实位置；缓存新鲜度按系统单调时钟检查，迟到位置由共享状态层阻止覆盖新位置。

应用暂停时停止系统位置更新和超时任务，恢复时重新订阅。位置开关关闭、临时没有提供器或权限暂不可用时，持续监听保留可恢复的逻辑 watch（暂停硬件订阅），不会释放其回调 ID；监听系统定位模式/提供器广播，重新开启后恢复同一个 watch。每次恢复先清理旧订阅和计时器，避免重复注册。只有调用方清除监听或 Activity 销毁才释放 watch 及回调；单次获取失败仍会结束并释放资源。不请求后台位置权限、不持久化坐标、不输出坐标日志。位置关闭、权限拒绝或没有可用提供器会返回错误。旧版本的精确超时后再次调用 Google 平衡精度策略已移除，避免两条请求同时卡住。新插件需要重新构建和安装 APK，仅刷新网页不能更新原生实现。

OPPO 等真机复测：确认系统位置服务开启，分别授予精确/粗略位置，首次冷启动等待上述获取窗口；在室内 Wi-Fi/移动网络和室外开阔处分别检查蓝点及精度圈。首次进入且系统定位关闭时显示不可用提示；成功定位后关闭开关，保留最后位置，不凭开关变化强制弹错；此时点击定位或主动刷新附近活动必须提示系统定位不可用。重新开启后应自动恢复同一个持续监听，无需重启应用。另测权限拒绝及恢复重试。取得位置后离开再进入地图、切换前后台及手动居中，确认没有重复监听。记录设备、Android/WebView、APK 版本、网络/信号环境和等待时间；不要记录真实经纬度。模拟器注入坐标和替身测试不能证明 OPPO 的实际 GPS/网络定位已恢复。

## 设备朝向

[device-heading.ts](device-heading.ts) 是地图朝向标的唯一平台入口。网页进入地图即优先启动 `AbsoluteOrientationSensor`（60Hz、`screen` 参考系），它会主动读取已有的当前姿态；不支持、未授权或被策略阻止时回退到 `deviceorientationabsolute` / `deviceorientation`。各网页读数以 `requestAnimationFrame` 合并同一帧中的更新，细微转向不会被阈值过滤。Android 通过本地 `DeviceHeadingPlugin`（`android/app/src/main/java/io/github/tomorikaho/livelife/dev/DeviceHeadingPlugin.java`）读取 `TYPE_ROTATION_VECTOR`，按当前显示旋转重映射后发送 0–360° 的磁北航向。传感器不可用或原生桥加载失败时，自动回退到 WebView 事件；在首个航向读数到来前，地图方向标默认指向北方，之后实时替换为传感器读数。

插件仅在地图页存在时订阅，应用暂停时注销传感器、恢复后重新订阅，离开地图或销毁 Activity 时清理。它不请求额外运行时权限，也不保存或上传传感器数据。Android 验收时，先授予位置权限，在 2D 和 3D 地图缓慢旋转设备，确认标记连续转动；再旋转屏幕、切换后台和前台、离开再进入地图，确认朝向保持可用且没有重复监听。
